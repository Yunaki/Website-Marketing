§ guardrails · the walls

An agent here can read, judge, and draft. It can never send, sign, or file.

You hold immigration clients' lives in your file system. So the rules below are not policies we ask a model to follow — they are walls built into the system, enforced in code, and tested on every change.

§01 · what can never happen

Structural, not prompted.

01

Nothing sends without a human

the send gate

Every message an agent writes is born as a pending draft. An attorney approves it; dispatch is a separate, deliberate press. The drafting code physically cannot send — the sending code path only accepts human-approved drafts.

02

Nothing is signed or filed

unfillable by construction

Signature, consent, and barcode fields are rejected at the level where form fields are defined — they cannot be mapped, filled, or touched. There is no e-filing integration and no submit automation anywhere in the product. Filing is your attorney's act, always.

03

No plausible guesses

null over guess

A value that is absent, blank, or illegible is recorded as null. The case check's third verdict — undeterminable — exists so the system says "I can't tell" instead of accusing your client or passing an incomplete answer as complete. Failure resolves to uncertainty, never to a pass.

04

Firm isolation, twice

two walls per query

Every database read is scoped to your firm in the application code and again by row-level security in the database itself. A request for another firm's record returns the same answer as a record that doesn't exist.

05

The party wall

one case, two halves

A petitioner and a beneficiary can share a case without sharing answers. Portal links are scoped per party, and a check triggered by one party's submission reads only that party's half — it can never report the other side's unanswered questions.

06

No client words in logs

ids, counts, hashes

Logs and traces carry identifiers, counts, and content hashes — never a question, an answer, an address, or a filename. Documents are referenced by cryptographic hash. Even the agent's own summaries are audited so they cannot quote a client back.

07

Pinned capabilities

allow-lists, not vibes

Each agent has an explicit, build-time-checked list of tools — the complete answer to "what can this agent do." Anything else is refused at the execution layer. Budgets cap every run; a run that hits its cap says so instead of pretending it finished.

08

Everything on the record

audit by default

Every agent run files a durable record — what it read, what it did, in what order, and how it ended — on success, on error, and on cap alike. The case check panel shows your firm the same trace.
